## Design decisions worth recording

- **No manager scoping on profile bulk.** Profiles are instance-global and no profile endpoint has ever been scope-filtered; the bulk endpoint does not invent scoping it would be the only reader of. This is the single deliberate divergence from `subscribers/bulk.go`, commented in `selectTargets`.
- **Profile import checks duplicate names itself.** `subscribers.username` is unique so `POST /api/v1/subscribers` 409s a duplicate, giving the subscriber import idempotency for free. `profiles.name` is **not** unique and the create endpoint accepts a duplicate name — so the profile importer checks the live table per row (dry-run and immediately before execute-dispatch) and skips, rather than leaning on a 409 that never comes. A `profiles.name` uniqueness constraint was considered and rejected: it is a behavior change to an endpoint outside this FR's scope.
- **The importer is generalized, not duplicated.** One wizard, batch-table set, report shape, and self-dispatch mechanism serve both entities; the shared `{batch}` routes authenticate then enforce the batch's own entity permission in-handler (a single route guard can't know the entity before loading the batch).
